# SiliconForge IDE

Arduino-simple embedded IDE for C++ (Arduino), C, Rust and MicroPython. See [MAIN_IDEA.md](MAIN_IDEA.md) for the full vision.

```sh
npm install
npm start          # launch the IDE
npm test           # scaffold, marketplace, lint and error-parser tests
npm run examples   # rewrite examples/ after changing scripts/gen-examples.js
```

## How it works

- **New Project** picks a board from `src/boards.json` (plus every board of the cores installed through the Boards
  Manager) and a language, then `src/scaffold.js` writes the project (`.ino` sketch, CMake + linker script,
  Cargo + `memory.x`, or `main.py`/`boot.py`) plus a `siliconforge.json` manifest.
- **Examples** live in `examples/<board>/<example>/<language>/`, generated by `scripts/gen-examples.js`. Opening one
  makes a private copy as a new project. Bare-metal Cortex-M C, Rust and megaAVR have only a `hello` example, since
  their registers differ per chip; use the C++ language on those boards for servo, serial and the rest.
- **Libraries** (Ctrl+Shift+I) searches the Arduino index for C++ projects, crates.io for Rust (`cargo add`) and
  micropython-lib for MicroPython (`mpremote mip install`, added to Upload). Bare-metal C has no index.
- **Boards** (Ctrl+Shift+B) installs Arduino cores. ESP32, ESP8266, Pico and STM32 indexes are built in; add others
  under *Additional board URLs*.
- **Code checks**: `renderer/lint.js` flags common mistakes while typing, with quick fixes on the lightbulb. On save,
  the manifest's `lint` steps run the real compiler with warnings on, shown as squiggles. C++ sketches and MicroPython
  get completion and hover from `renderer/api.js`. A missing-header error offers *Find a library*.
- **Port** set to `auto` uses the only plugged-in board; click the field to choose among detected ports.
- **Board options** (AVR programmer, debug probe, ESP32 flash size and upload speed) are picked in the wizard. Click the
  board badge in the toolbar to move the open project to another board on the same toolchain or change its options:
  generated files you have not edited are regenerated, edited ones are kept and listed in the console.
- **Verify / Upload** run the manifest's `build` / `build + upload` shell steps. Edit them per project; `{port}` is
  replaced with the toolbar Port value. The special step `touch-1200` (Leonardo, Micro, Nano Every) opens the port at
  1200 baud to reset the board into its bootloader, then points `{port}` at whatever port the bootloader appears on.
- Compiler output is parsed (`src/errors.js`) into clickable console lines and editor squiggles.
- **Menu bar** holds every command; **Customize** covers themes, accent color, spacing, toolbar buttons and shortcuts. The
  command palette is Ctrl+Shift+P or F1.
- **Extensions** add themes, snippets and commands, and run in a sandbox. See [extensions/README.md](extensions/README.md).
- **Serial Monitor** uses Web Serial; the **Plotter** graphs lines of comma/space-separated numbers, and `name:value`
  pairs label the channels as in the Arduino IDE.

## Toolchains (must be on PATH for now)

| Project type | Tools |
|---|---|
| C++ (Arduino), Libraries, Boards | `arduino-cli` |
| C, STM32/nRF | `cmake`, `ninja`, `arm-none-eabi-gcc`, `openocd` |
| C, Arduino Uno | `avr-gcc`, `avrdude` (found automatically if Arduino IDE / `arduino-cli core install arduino:avr` installed them) |
| C, ESP32 | ESP-IDF (`idf.py`, `IDF_PATH`) |
| C, Pico | Pico SDK (`PICO_SDK_PATH`), `cmake`, `ninja`, `picotool` |
| Rust | `rustup` (target installed automatically from `rust-toolchain.toml`), `probe-rs` |
| MicroPython | `python`, `mpremote` |
